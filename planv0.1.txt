# Plan: Cerberus v0.1 — Four-Tool Agent-Swarm Build (≈24h to "5:10")

## Context
The repo is **docs-only** today (no code). The goal: go from spec → a **runnable v0.1** in ~24h by running a **4-tool agent swarm** in parallel on one laptop — Claude Code agents + Cursor (Pro) + Antigravity (Pro) + Codex (2.5k credits). Confirmed targets:
- **Scope:** max breadth — all 11 verticals scaffolded, compiling, unit-tested, documented.
- **Demo (acceptance test):** two `cerberusd` nodes discover each other and one runs a **capability-gated WASM task** on the other, result returned over the wire, driven from the `cerberus` CLI.
- **Quality bar:** product-grade *for the slice covered* (clean interfaces, tests, CI green, tagged `v0.1.0`). Not a fully-featured hypervisor — many pieces stay documented stubs (zk-WASM, RDMA-over-TB, host-TEE = Frontier).

> Honest note baked into the plan: agents generate code fast, but **integration + compile-fix + E2E wiring is serial**. The plan front-loads a shared frozen contract so parallel work doesn't collide, and reserves a large integration phase.

## Orchestration model
**Conductor = this Claude Code session.** Owns: the frozen contract, the `main` integration branch, CI, code review, FFI wiring, and the final demo. The four tools each own a **disjoint lane** on its **own git worktree + branch**, so no two ever edit the same file.

| Lane | Tool | Owns (verticals) | Dirs it may touch | Language |
|---|---|---|---|---|
| **A — Core** | **Claude worktree-agents** (spawn ≤5, one per vertical) | 00 OCap, 02 CRDT, 03 Runtime, 04 9P, 06 Scheduler | `core/ocap`, `core/crdt`, `core/runtime`, `daemon/ninep`, `daemon/scheduler` | Rust + Go |
| **B — Fabric** | **Cursor Pro** background agents | 01 Mesh, 07 Identity, 08 Observability | `daemon/mesh`, `core/identity`, `daemon/telemetry` | Go + Rust |
| **C — Surface** | **Antigravity Pro** | 05 Economy, 09 Lifecycle, 10 Desktop | `core/economy`, `daemon/lifecycle`, `tray/`, `cmd/` | Rust + Go + Tauri |
| **D — Platform** | **Codex** (many parallel tasks) | codegen, CI, test harness, E2E, examples, fixer-swarm | `proto/`, `components/`, `build/`, `.github/`, `test/` | polyglot |

**Collision avoidance (hard rules):**
- One repo; each lane runs in its own `git worktree` dir on branch `ws/core | ws/fabric | ws/surface | ws/platform`.
- **The frozen contract** (`proto/`, `components/wit/`, `schemas/`) is generated in Phase 0, committed to `main`, and **nobody edits it unilaterally** — lanes consume generated bindings only.
- Disjoint directory ownership (table above). Merge to `main` only when **standalone-green**; the conductor integrates.

## Phase 0 — Foundation (serial, ~1–2h) — UNBLOCKS EVERYTHING
Do this before any fan-out (conductor + Codex pair):
1. **Monorepo skeleton:** `go.work` (Go workspace), root `Cargo.toml` (Rust workspace), `Taskfile.yml` (go-task), `.github/workflows/ci.yml`, `.editorconfig`, `LICENSE`.
2. **`CLAUDE.md` + `CONTRACT.md`** — rules of engagement every tool (even non-Claude) follows: directory ownership, "don't touch `proto/`", interface conventions, test/lint commands. (Use `/init`.)
3. **Contract-as-code:** ARCHITECTURE §3 → `proto/*.proto` (telemetry, crdt op, compute task), `components/wit/*.wit` (`caps` world), CDDL/CBOR for capability + settlement, JSON-schema for profile. Generate Go + Rust bindings (`buf generate`, `wit-bindgen`).
4. **FFI keystone:** `core/cabi` C-ABI header + cgo skeleton so Go↔Rust links with opaque `u64` capability handles (keep the boundary tiny).
5. **Worktrees + branches** created; per-lane brief = its vertical doc(s) + `CONTRACT.md` + generated bindings.

## Phase 1 — Parallel build (~12–16h overlapping wall-clock)
Each lane builds its verticals to **scaffolded + compiling + unit-tested**, stubbing cross-lane deps behind the contract. Foundations to clone/vendor (don't build from zero):

**A — Core (Claude agents):**
- `00 OCap` (Rust): capability CBOR (`ciborium`), Ed25519 (`ed25519-dalek`), mint/attenuate/verify, cap table, WIT host on **`bytecodealliance/wasmtime`** component model. CapTP-lite stub. Ref: wasmtime examples, `ocapn` spec.
- `02 CRDT` (Rust): wrap **`automerge/automerge`** (or **`y-crdt/y-crdt`**); doc apply/merge, vector clock, domain reducers, belief-conflict flag.
- `03 Runtime` (Rust): wasmtime component host; load+run component; `gpu` capability dispatch behind a trait (MLX/wgpu stub); promise-pipelining stub. Ref: `bytecodealliance/wit-bindgen`, `cargo-component`.
- `04 9P` (Go): 9P2000.L server via **`hugelgupf/p9`**, mount via **`hanwen/go-fuse`** (+ **`winfsp/cgofuse`** on Win); cap-gated walk/open; ctl→endpoint.
- `06 Scheduler` (Go): telemetry-driven greedy constrained bin-packer; re-route on event; hot standby.

**B — Fabric (Cursor):**
- `01 Mesh` (Go): **`eclipse-zenoh/zenoh`** (zenoh-go/c-binding) intra-site + **`libp2p/go-libp2p`** + `go-libp2p-pubsub` (gossipsub) + **`quic-go/quic-go`**; mDNS discovery; OTP supervision via **`thejerf/suture`**.
- `07 Identity` (Rust): keygen, attestation envelope (TEE stub), revocation OR-set (reuses 02), `cap_verify`/`is_revoked` seam.
- `08 Observability` (Go): **`open-telemetry/opentelemetry-go`** spans over Zenoh; telemetry publisher; trace-context in CapTP frames.

**C — Surface (Antigravity):**
- `05 Economy` (Rust): minimal eUTXO ledger, optimistic settlement + fraud-proof re-exec, wallet WIT resource, IPLD fetch via **`ipld/go-ipld-prime`**; erasure via **`klauspost/reedsolomon`**; zk-WASM = documented stub (ref **`DelphinusLab/zkWasm`**).
- `09 Lifecycle` (Go): power/thermal/sleep via **`shirou/gopsutil`** + OS APIs; events, checkpoint hook, capability hand-back.
- `10 Desktop` (Go+Tauri): **`tauri-apps/tauri`** v2 tray + **`spf13/cobra`** CLI (`cerberus`) + `cerberusd` skeleton + gRPC-over-UDS IPC + OpenAI-compatible gateway stub.

**D — Platform (Codex):** proto/WIT codegen pipeline (**`bufbuild/buf`**), CI (build/test/`golangci-lint`/`clippy`, cross-compile matrix), **the E2E demo harness** (`test/e2e` spins 2 `cerberusd`, runs the WASM task, asserts result), example WASM components (`hello-shard`, toy matmul) via `wit-bindgen`, Dockerfile/devcontainer, packaging (**`goreleaser`**), and a **compile-error/test-failure fixer swarm** across all branches.

## Phase 2 — Integration (conductor, ~4–6h)
- Merge order: `ws/platform` → `main`, then `ws/core` → `ws/fabric` → `ws/surface`, each gated on standalone-green.
- Wire real seams: **A↔B** (real Zenoh transport + real `cap_verify` + revocation), **A↔C** (real compute completion → settlement/lifecycle), **C↔core** (desktop → real daemon IPC). Resolve Go↔Rust FFI for real.
- Run `/code-review` (optionally `/code-review ultra`) before each merge; `/security-review` on the OCap kernel + capability paths.

## Phase 3 — Demo + harden + ship (~2–3h)
- **Acceptance:** `task demo` → 2 `cerberusd` discover each other → `cerberus run hello-shard.wasm --on <peer>` → capability-gated remote execution → result returned. Scripted in `test/e2e`; confirm with `/run` + `/verify`.
- Polish: README quickstart, `task demo` target, CI badge, tag `v0.1.0`. Push to a **branch** (not `main` directly — policy).

## Skills to use (Claude side)
`/init` (Phase 0 CLAUDE.md) · `engineering:testing-strategy` (per-lane test plans) · `engineering:architecture` (ADRs if drift) · `/code-review` + `/code-review ultra` (pre-merge) · `/security-review` (OCap) · `/run` + `/verify` (prove the demo) · worktree-isolated `Agent` spawns (the A-lane builders) · `/loop` (babysit long CI/agent cycles).

## Per-tool paste-in briefs (created during execution)
`docs/agent-briefs.md` — one ready-to-paste prompt per external tool (Cursor/Antigravity/Codex), each = its vertical doc(s) + `CONTRACT.md` + dir-ownership + "don't touch `proto/`" + the standalone test target from [docs/workstreams.md](../../E:/10w10p/Cerberus/docs/workstreams.md).

## Risks & mitigations
- **Go↔Rust FFI = #1 time sink** → cabi skeleton in Phase 0, opaque-handle boundary only.
- **zenoh-go maturity** → fallback to libp2p-only intra-site for the demo (demo needs only discovery + one stream).
- **Cross-tool interface drift** → frozen contract + generated bindings; nobody edits `proto/`.
- **Agent file collisions** → worktrees + disjoint dirs (hard rule).
- **wasmtime/component-model churn** → pin versions; start from a known-good component example.
- **One-laptop build thrash** → stagger heavy Rust (clippy) vs Go builds; cap concurrent full builds.

## Verification / Definition of Done
- `task build` (all langs compile) · `task test` (unit green) · `task lint` clean · `task demo` (2-node remote WASM exec passes) · `/security-review` clean on OCap.
- Checklist: 11 verticals compile + unit-tested + doc-linked; demo path runs; CI green; `v0.1.0` tagged; `docs/agent-briefs.md` present.

# (PRIOR) Plan: Cerberus Implementation Workstream Division

## Context (current task)

The Volume II architecture docs are complete and committed. The user now wants the *implementation work* divided into **three independent workstreams** that (a) each follow the single frozen schema contract, (b) can be built and tested standalone, (c) integrate cleanly at the end, and (d) club related verticals together. The split concentrates the most technically novel/interesting work in the first workstream.

> Constraint: the relative sizing of the workstreams must **not** be stated as a ratio or percentage anywhere in the output docs or commit messages. Present the three workstreams neutrally as peers.

### The integration contract (the thing that makes independence possible)
[ARCHITECTURE.md §3](../../E:/10w10p/Cerberus/ARCHITECTURE.md) + [docs/schemas/schemas.md](../../E:/10w10p/Cerberus/docs/schemas/schemas.md) are declared **FROZEN**. Every workstream codes against these (capability CBOR/CDDL, telemetry proto3, CRDT op envelope, compute task + promise, 9P namespace + op→cap table, settlement CDDL, WIT worlds, IPC gRPC, error codes). Anything a workstream *consumes* from another is mocked/stubbed behind the schema until integration.

### The three workstreams (vertical clubs)
- **Workstream A — Core Compute & Cognition Plane** (the spine + brains + novel execution): `00` OCap kernel, `02` CRDT state, `03` compute orchestration (WASM/sharding/promise pipelining), `04` 9P peripheral virtualization, `06` placement & scheduling brain. Owns the capability mechanism and the WIT host. This is where the fascinating distributed-systems work lives.
- **Workstream B — Connectivity & Trust Fabric**: `01` mesh fabric & transport (Zenoh+libp2p/QUIC/supervision), `07` identity & capability lifecycle (bootstrap/attestation/revocation), `08` observability & tracing. Theme: how nodes find each other, prove identity, and are observed.
- **Workstream C — Economy, Lifecycle & Surface**: `05` eUTXO & Open Mesh economy (profile-gated/optional), `09` power-thermal-sleep lifecycle, `10` desktop app model (daemon/CLI/tray/gateway). Theme: the optional economy, the node's physical edge behavior, and the human/external surface.

### Cross-workstream seams (interface stubs)
| Workstream | Consumes (stub until integration) | From |
|---|---|---|
| A | live telemetry feed; real transport; identity/revocation verifier | B (`08`,`01`,`07`) |
| B | `cap_verify`/`is_revoked`; CRDT engine for revocation OR-set | A (`00`,`02`) |
| C | capability + `wallet` handles; completed `ComputeTask`; scheduler lifecycle hooks | A (`00`,`03`,`06`) |

Note the tight coupling between `00` (capability *mechanism*, in A) and `07` (capability *lifecycle*, in B): the seam is the `cap_verify`/`is_revoked` API + the revocation OR-set CRDT doc (`sys/revocations`). Both are already in the frozen schema, so each side builds against it independently.

## Deliverables
1. **`docs/workstreams.md`** — master work-division doc: the frozen-contract declaration, the three workstreams (scope, owned verticals, headline stack, standalone build target, standalone test plan, consumed seams + stubs), the integration milestone ladder, and a suggested branch/worktree strategy. **No ratios/percentages.**
2. **A one-line header banner** added to each of the 11 vertical docs: `> **Workstream:** <A|B|C — name> · Depends on: <list> · Stub until integration: <list>`. Helps a developer working a single vertical know their lane and seams.
3. **A "🔒 Frozen Integration Contract" banner** added to the top of `docs/schemas.md` and a one-line note in `ARCHITECTURE.md §3`.

## Standalone test strategy (per workstream, drawn from each vertical's §5/§9)
- **A:** single-process multi-node *simulation* — mint caps, run a toy WASM component, shard a tiny model across simulated nodes, merge CRDT memory, schedule placement. Mocks: transport loopback, synthetic telemetry, always-valid cap verifier.
- **B:** 2–3 real OS processes — Zenoh+libp2p discovery, attested admission, telemetry/trace collection, with stub workloads (no real compute). Mocks: stub cap mechanism.
- **C:** standalone modules — settle mock tasks (eUTXO + optimistic proof), drive lifecycle from simulated power events, run daemon+CLI+tray against a stub core. Mocks: stub core/scheduler/wallet.

## Integration milestone ladder (verification)
1. **Contract freeze** (done — schemas locked).
2. **Standalone green:** each workstream's own test suite passes against mocks; each ships a runnable standalone binary/lib.
3. **Pairwise:** A↔B (real transport + real cap verify + real revocation), then A↔C (real compute completion → real settlement/lifecycle).
4. **Full mesh E2E:** all three on one mesh; run the [ARCHITECTURE.md §4](../../E:/10w10p/Cerberus/ARCHITECTURE.md) walkthroughs — "2 GiB remote VRAM request," "lid-drop mid-pipeline," "Open Mesh cross-org trade" — as the acceptance tests.
