Getting started

Cerberus is a zero-trust, masterless distributed hypervisor. You run a small daemon (cerberusd) on each machine you own; they discover each other on your LAN with no configuration and become a single private mesh. Software on the mesh can only touch a resource it has been handed an unforgeable capability for.

If you haven't installed yet, start with the install guide. The rest of this page assumes you can run cerberusd (from an installed build or a source checkout).

First run: start the daemon

go run ./cmd/cerberusd
# or run an installed binary: cerberusd

On startup you'll see the daemon compose the mesh and bring up its surfaces:

cerberusd v0.1.0  profile=open_mesh  kernel=pure-go-stub  sample-cap=1
cerberusd: composed system up (mesh + telemetry + scheduler + 9P under supervisor)
mesh: dialable at /ip4/192.168.1.24/udp/54613/quic-v1/p2p/12D3KooW...
Starting Gateway on :8080 (Bearer token required)
Starting status API on 127.0.0.1:7777 (Bearer token required)
Starting metrics on 127.0.0.1:7779 (/metrics token-gated; /healthz /readyz open)
Starting RPC server on 127.0.0.1:9092

i Profiles. cerberusd defaults to -profile=open_mesh (the compute economy is on; the daemon mints genesis credits). Use -profile=sealed for the economy-off, attestation-on mode.

The operator token

Cerberus has no ambient authority — every network surface requires a capability token. On first start the daemon mints an operator token (subject operator, admin rights, 24-hour TTL) and writes it to your OS config directory. The CLI reads it automatically.

OSPath
Windows%AppData%\cerberus\operator.token
macOS~/Library/Application Support/cerberus/operator.token
Linux~/.config/cerberus/operator.token

To use it in a shell (for curl, Python, etc.), load it into an environment variable:

# Linux / macOS
export CERBERUS_TOKEN="$(cat ~/.config/cerberus/operator.token)"
# Windows (PowerShell)
$env:CERBERUS_TOKEN = Get-Content "$env:AppData\cerberus\operator.token"

The token is written owner-only (0600) — treat it like an SSH key. It expires after 24h; restart the daemon to rotate it.

Pairing machines

This is the moment Cerberus becomes a mesh. Each node runs cerberusd. The daemon now binds the mesh on all interfaces by default (--mesh-listen /ip4/0.0.0.0/udp/0/quic-v1), so it's reachable from other machines, and it logs its dialable address(es) at startup: 

mesh: dialable at /ip4/192.168.1.24/udp/54613/quic-v1/p2p/12D3KooW...

That full /ip4/<ip>/udp/<port>/quic-v1/p2p/<peer-id> string is the node's multiaddr — the thing another machine dials to pair explicitly.

Same LAN — zero config

If both machines are on the same local network, there is nothing to configure. Each daemon advertises and browses the _cerberus mDNS service on the subnet and connects to peers it finds over libp2p/QUIC. Just start the daemon on the second machine: 

go run ./cmd/cerberusd    # on the second machine — that's it

Within a few seconds the two daemons discover each other.

! Both machines must be on the same L2 subnet for mDNS multicast to reach. Many corporate/guest Wi-Fi networks block multicast and client-to-client traffic — use a home/office LAN or a wired switch. If mDNS is blocked, use the cross-network path below.

Different networks (or mDNS blocked)

When the machines aren't on the same subnet — or multicast is blocked — give them a shared, stable address space with Tailscale, then pair explicitly with --peer.

  1. Install Tailscale on both machines. Each gets a stable 100.x.y.z IP that works across networks.
  2. On node A, start the daemon and read its dialable multiaddr from the startup log — the one using its Tailscale IP (a 100.x.y.z address): 
    mesh: dialable at /ip4/100.101.102.103/udp/41000/quic-v1/p2p/12D3KooW...
  3. On node B, start the daemon pointed at node A's Tailscale multiaddr: 
    cerberusd --peer /ip4/100.101.102.103/udp/41000/quic-v1/p2p/12D3KooW...

--peer takes a comma-separated list, so you can bootstrap against several nodes at once:

cerberusd --peer /ip4/100.101.102.103/udp/41000/quic-v1/p2p/12D3Koo...,/ip4/100.64.10.5/udp/41000/quic-v1/p2p/12D3Koo...

To pin a firewall port (so the QUIC port is predictable instead of ephemeral), set a fixed UDP port on the listen address:

cerberusd --mesh-listen /ip4/0.0.0.0/udp/4001/quic-v1
i mDNS still runs on each node's LAN as usual — --peer is additive, covering peers that discovery can't reach. WireGuard or any other overlay that gives each machine a routable IP works the same way as Tailscale.

Security model

Cerberus is built on object capabilities, not identities. There are no passwords, no roles, and no ambient authority — you can't do something just because of who you are. You can only do something if you hold a capability for it.

Capabilities, not passwords

Every cross-boundary action presents an unforgeable capability handle. No shared secret grants blanket access; there is nothing to phish or replay across resources.

Revocable Ed25519 tokens

Each capability is an Ed25519-signed token you can narrow (attenuate), delegate, and revoke. Revocations gossip mesh-wide over a capability-gated topic and survive a restart, so a revoke on one node becomes a deny everywhere.

WASM sandbox for agents

Agent workloads run as WebAssembly components in a wazero sandbox. A guest sees only the capabilities it was imported — it cannot reach the host or other resources by default.

Issuer key in the OS keychain

The daemon's root signing key is kept in OS-native custody where available — Windows Credential Manager, macOS Keychain, or the Linux Secret Service — falling back to a 0600 file on headless hosts.

! Maturity, honestly. This is early beta. The default build uses the pure-Go OCap kernel; a real Rust kernel exists behind a build flag. There has been no external security audit yet. Frontier features (zk-WASM proof-of-inference, host-TEE memory shielding) are experimental and off by default. Treat Cerberus as LAN-trusted infrastructure — don't rely on it for sensitive or production workloads.

CLI reference

cerberus is the operator's control client. It talks to a running cerberusd over the local RPC socket (127.0.0.1:9092) and authenticates every call with a capability token — resolved from $CERBERUS_TOKEN if set, otherwise the operator token file the daemon writes. 

cerberus [--json] <command> [args]
# run without a command to print full usage
CommandWhat it does
statusDaemon health, identity, uptime, credit balance
doctorDiagnose daemon discovery + reachability (use this to confirm pairing)
nodesList mesh peers (this node + connected)
run <component.wasm> [--on <peer>]Execute a WASM workload and print the real result
devicesList the 9P namespace devices
wallet [owner]Compute-credit balance from the durable ledger
caps mint / attenuate / revoke / listMint, narrow, revoke, and list capability tokens
components add / listRegister and list local WASM components
conflicts list / resolveInspect and resolve open CRDT belief conflicts
economy challenge <tx-id> …Dispute a pending settlement with a fraud proof
metricsFetch the local Prometheus /metrics text
versionPrint client + contract version

cerberus status
