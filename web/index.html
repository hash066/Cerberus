Zero-trust distributed hypervisor

Bind your own machines into one capability-secured mesh that runs AI agents.

Run one small daemon on each Mac, PC, or Linux box you own. They discover each other on your LAN with zero configuration and become a single private mesh — where software can only touch a resource if it holds an unforgeable capability for it. No master node, no cloud account, no ambient authority.

What it is

A private compute mesh, made of the machines you already have.

The desktop app is a background daemon (cerberusd) plus a system-tray dashboard. Start it on two or more machines and they pool into a mesh you control end to end — no accounts, no broker in the middle.

Masterless & zero-config

Nodes auto-discover over mDNS on the LAN and coordinate directly over libp2p/QUIC. Any node can drop without killing the mesh.

Zero-trust by construction

No passwords or roles. Every action presents an Ed25519 capability you can narrow, delegate, and revoke — revocations gossip mesh-wide and survive restart.

Heterogeneous by default

Workloads compile to WebAssembly components, so an ARM Mac and an x86 PC run the same sandboxed shard — no cross-compiling native binaries.

OpenAI-compatible gateway

Point any OpenAI SDK at http://localhost:8080/v1 with your token and dispatch a compute task to the mesh through the real WASM executor.

Two profiles, one binary

open_mesh (compute economy on) and sealed (economy off, attestation on) — a boot-time switch, no separate build.

Durable & observable

Issuer key, revocations, the credit ledger, and CRDT checkpoints persist across restarts. Prometheus metrics, health probes, and a live status API back the tray dashboard.

How it fits together

One daemon per machine. Capabilities on every edge.

Prove it end to end

Two daemons, one WASM shard, across the mesh.

The acceptance demo spins up two real cerberusd processes, has them discover each other over the real mesh, and runs a WebAssembly module remotely from one to the other.

# from a clone of the repo — builds the daemon and runs a shard across two nodes
go run ./test/e2e
DEMO PASSED: hello-shard.wasm ran remotely on worker and returned 1337.

That 1337 is a real WebAssembly module executed on the other node and returned over a capability-gated stream.

Maturity, honestly

What's real today — and what isn't yet.

Real & tested

  • Zero-config LAN discovery + libp2p/QUIC mesh, masterless
  • Ed25519 capability tokens gating every network surface
  • Real WebAssembly execution (wazero) — remote shard returns 1337
  • Durable state (issuer key, revocations, ledger, CRDT checkpoints)
  • Distributed revocation gossip across nodes
  • Metrics, health, status API, OpenAI-compatible gateway path

Stub / hardware-gated

  • Gateway content is the demo shard, not a live LLM (path is real)
  • GPU dispatch (wgpu/MLX) — off by default, needs real GPU hardware
  • FUSE/WinFsp device mounts — labelled stub (needs a kernel driver)
  • OS mic/speaker capture — transport real, capture source stubbed
  • Frontier bets (zk-WASM, host-TEE, RDMA) — experimental, off

The default build uses the pure-Go OCap kernel. No external security audit yet. See the full matrix in VISION-AND-ROADMAP.md.
