Install

Install Cerberus

Cerberus ships as a desktop app: a background daemon (cerberusd) and a system-tray dashboard. Install it on every machine you want in the mesh. Pick your OS below, or build from source — the same code builds on all three.

! Signed release binaries don't exist yet. Beta downloads live on the project's GitHub Releases page. If your platform's build isn't posted, use build from source.

Windows 10 / 11

  1. Download Cerberus_x.y.z_x64_en-US.msi (installer) or Cerberus_x.y.z_x64-setup.exe (standalone setup) from GitHub Releases. Either one installs the same app.
  2. Run it. Because the build is unsigned, SmartScreen shows “Windows protected your PC.” Click More info → Run anyway.
  3. The tray app launches cerberusd in the background and adds a wolf icon to your system tray. Open it to see the Overview dashboard.
i The daemon binds the mesh on all interfaces by default and writes an operator token to %AppData%\cerberus\operator.token. Allow it through the Windows Firewall (UDP) when prompted so peers can reach it.

Prefer the command line? The daemon builds pure-Go — see Build from source.

macOS (Apple Silicon & Intel)

! There is no macOS download yet. The current release ships Windows installers only — no .dmg has been published. Build from source below; it is the same code, on both Apple Silicon and Intel.
  1. Follow Build from source to get cerberusd and the cerberus CLI. The daemon is pure-Go and needs no C toolchain.
  2. Want the desktop app too? It needs Node and the Tauri CLI: cd tray && npm install && npm run tauri build.
  3. A locally built app is unsigned, so Gatekeeper blocks the first launch. Right-click the app → Open, then confirm Open. (Or: System Settings → Privacy & Security → “Open Anyway”.)
i If Gatekeeper is stubborn, you can clear the quarantine attribute from a terminal: 
xattr -dr com.apple.quarantine /Applications/Cerberus.app

The daemon writes its operator token to ~/Library/Application Support/cerberus/operator.token. Approve the local-network prompt so peers can discover this Mac.

Linux

! There is no Linux download yet. The current release ships Windows installers only — no .deb or .AppImage has been published. Build from source below.

The daemon and CLI are pure-Go and build in one command:

git clone https://github.com/hash066/Cerberus.git
cd Cerberus
go build ./cmd/cerberusd ./cmd/cerberus
./cerberusd
i Headless server? The daemon is all you need — it is the whole node, and the desktop app is only a dashboard. If you do want the tray app, it needs a WebKitGTK runtime (libwebkit2gtk-4.1) and an app-indicator library (libayatana-appindicator3) for the tray icon to appear.

The daemon writes its operator token to $XDG_CONFIG_HOME/cerberus/operator.token (usually ~/.config/cerberus/operator.token).

Build from source

The most reliable path during the beta. The daemon and CLI are one Go module and build pure-Go with no C toolchain. Rust (Cargo) is only needed for the core/ crates and tests; the Tauri toolchain is only needed for the desktop tray app.

Prerequisites

ToolVersionNeeded for
Go1.22+the daemon, CLI, gateway, mesh (required)
Rust (cargo)stablethe core/ crates + cargo test (recommended)
gitanycloning the repo
Node + Tauri CLINode 18+ / Tauri v2only for the desktop tray app
taskv3 (optional)the task build / test / demo shortcuts

1. Clone and build the daemon + CLI

git clone https://github.com/hash066/Cerberus.git
cd Cerberus

# build everything (Go + Rust):
task build
# …or without the task runner:
go build ./...        # daemon, CLI, gateway, mesh (pure-Go, no C toolchain)
cargo build           # optional; builds the Rust core crates

2. Prove it works, then start a node

# two daemons discover each other and run a WASM shard remotely:
go run ./test/e2e     # or: task demo
DEMO PASSED: hello-shard.wasm ran remotely on worker and returned 1337.

# start the daemon (leave it running):
go run ./cmd/cerberusd

On startup the daemon serves the gateway (:8080), status API (127.0.0.1:7777), metrics (127.0.0.1:7779), and RPC (127.0.0.1:9092), and logs its dialable mesh address(es). See Getting Started for the full walkthrough.

3. Build the desktop tray (optional)

The tray is a Tauri v2 app. It needs Node, the Tauri CLI, and a native webview (WebView2 on Windows, WKWebView on macOS, WebKitGTK on Linux).

# with the daemon running, in another shell:
cd tray
npm install
npm run tauri dev     # dev window; use `npm run tauri build` for an installer
✓ No desktop handy? Open tray/preview.html in any browser — it's a self-contained static mock of the full dashboard, clearly labelled, so you can see the UI without the Tauri toolchain or a running daemon.
